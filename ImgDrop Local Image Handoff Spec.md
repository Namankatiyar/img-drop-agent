# ImgDrop: Local Image Handoff Spec

*Draft v1 · 6 Oct 2026 · Phone app → laptop server (Bun + Express + SQLite) → Python agent hook*

## 1. Goal

A phone app compresses one or more photos and uploads them as a single timestamped **group** to a server on the laptop, over the phone's own hotspot LAN. A Python hook runs at the start of an agent session, fetches the newest unclaimed group, and puts it in the agent's context, so the agent starts working without being told anything.

## 2. Scope

**In scope:** native phone app, local server, SQLite metadata, filesystem image storage, LAN discovery, agent session hook.

**Out of scope (v1):** cloud hosting, S3/MinIO, accounts or multi-user, HTTPS, resumable chunked uploads, offline queue, server-side image processing, a deletion UI.

## 3. Assumptions

- The phone hosts the hotspot, the laptop is joined to it, and both are on the same private subnet and always in range.
- One user, one phone, one laptop.
- The phone client is a native app, so plain HTTP to a LAN host is allowed with the right platform config.
- The laptop's IP comes from the phone's DHCP server. It is usually stable but not guaranteed (randomized MAC, hotspot restart), so the app finds the server by discovery rather than a hardcoded IP.
- Only the server process touches SQLite and the storage directory. The hook goes through the API.

## 4. Architecture

```
Phone (hotspot host)                    Laptop (joined to hotspot)
+----------------+   POST /groups     +--------------------------------------+
| native app     |------------------->| Bun + Express  (0.0.0.0:8000)        |
| - compress     |   (multipart,      |   +- bun:sqlite  data/app.db         |
| - discover     |    bearer token)   |   +- data/storage/<group_id>/*.webp  |
|                |<--- UDP beacon ----|   +- UDP beacon (port 41716)         |
+----------------+                    |                                      |
                                      | Agent session hook (Python)          |
                                      |   GET 127.0.0.1:8000/groups/latest   |
                                      |   -> ./inbox/<group_id>/ + context   |
                                      +--------------------------------------+
```

## 5. Stack

| Layer | Choice | Notes |
| --- | --- | --- |
| Runtime | Bun | Runs Express through its Node compatibility layer. |
| HTTP | Express 5 | Moving a route to `Bun.serve` later is easy if compatibility ever bites. |
| Database | `bun:sqlite` | Built in, synchronous, WAL mode. One writer is plenty. |
| Uploads | `multer` (disk storage) | Streams to a temp dir so memory stays flat. |
| IDs | `ulid` (monotonic) | Sortable by time, so ID order is upload order. |
| Discovery | `node:dgram` | UDP broadcast beacon. |
| Hook | Python 3, stdlib only | `urllib`, `json`, `pathlib`. No dependencies. |
| Phone app | TBD | Kotlin, Swift, Flutter or React Native. |

**Verify in the M0 spike on your Bun version:** multer's multipart streaming, `dgram` broadcast sending, and `bun:sqlite` WAL. If multer misbehaves, fall back to `busboy` or `Bun.serve` with `request.formData()` for that route only.

## 6. Data model

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

CREATE TABLE groups (
  id          TEXT PRIMARY KEY,                 -- ULID
  created_at  TEXT NOT NULL,                    -- UTC ISO-8601, set by server
  status      TEXT NOT NULL DEFAULT 'ready'
              CHECK (status IN ('ready', 'claimed')),
  claimed_at  TEXT,
  note        TEXT,                             -- optional text from the user
  client_key  TEXT UNIQUE,                      -- Idempotency-Key from the app
  image_count INTEGER NOT NULL
);

CREATE TABLE images (
  id         TEXT PRIMARY KEY,
  group_id   TEXT NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
  position   INTEGER NOT NULL,                  -- 1-based upload order
  file_name  TEXT NOT NULL,                     -- server-generated, e.g. 01.webp
  mime       TEXT NOT NULL,
  size_bytes INTEGER NOT NULL,
  UNIQUE (group_id, position)
);

CREATE INDEX idx_groups_status_id ON groups (status, id DESC);
```

A group is only inserted after all its files are safely on disk, so there is no `pending` state. The group row appearing is the commit point.

## 7. Storage layout

```
data/
  app.db
  config.json              # server_id + token, file mode 600
  storage/
    .tmp/<group_id>/       # in-flight uploads
    <group_id>/01.webp     # committed files
```

File names are generated by the server (`NN.<ext>` from the detected type). Client-supplied file names are never used for paths.

## 8. API

Auth: `Authorization: Bearer <token>` on everything except `GET /health`. Compare with `crypto.timingSafeEqual`. Errors use the shape `{ error: { code, message } }`.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/health` | Returns `server_id` and `version`. No auth. Used by the app to confirm it found the right server. |
| POST | `/groups` | Create a group from a multipart upload. |
| GET | `/groups/latest?unclaimed=1` | Newest `ready` group with its image list. `204` if none. |
| GET | `/groups?status=ready&limit=20` | Backlog listing, newest first. |
| GET | `/groups/:id` | One group with images. |
| GET | `/groups/:id/images/:position` | Streams the image file. |
| POST | `/groups/:id/claim` | Atomically `ready` to `claimed`. `409` if already claimed. |
| POST | `/groups/:id/release` | `claimed` back to `ready` (undo after a failed run). |

### POST /groups

- Content type `multipart/form-data`.
- Header `Idempotency-Key`: a UUID the app generates per group and reuses on retry.
- File field `images`: 1 to 20 files.
- Text field `note`: optional, up to 2000 characters.

Server steps:

1. Authenticate. If `client_key` already exists, return `200` with the existing group (no duplicate).
2. Generate the group ID. Stream files into `storage/.tmp/<group_id>/`.
3. Check each file's magic bytes (WebP, JPEG or PNG) and size. Reject the whole request on any failure and delete the temp dir.
4. Rename the temp dir to `storage/<group_id>/`.
5. In one SQLite transaction, insert the group (`ready`) and all image rows.
6. Return `201` with the group ID, `created_at`, `status` and `image_count`.

If step 5 fails, delete the renamed directory. If the process dies between 4 and 5, the startup sweep removes the orphan.

**Limits (configurable):** 20 files per group, 8 MB per file, 50 MB per request. After client compression a photo is typically a few hundred KB, so these are generous.

**Status codes:** `400` invalid upload, `401` bad or missing token, `404` unknown group or image, `409` already claimed, `413` too large, `415` unsupported type.

### Claim semantics

Claiming is a single statement: `UPDATE groups SET status='claimed', claimed_at=? WHERE id=? AND status='ready'`. Zero rows changed means `409`. The hook claims only after every file has been written locally.

## 9. Discovery and pairing

### Pairing (once)

On first start the server generates a random `server_id` (128-bit hex) and `token` (256-bit) and stores them in `data/config.json`. On every start it prints a QR code in the terminal encoding `imgdrop://pair?id=<server_id>&token=<token>&port=8000`. The app scans it once and stores the ID, token and last known address.

### Beacon

The server broadcasts a small UDP packet every 3 seconds. This is the same idea KDE Connect uses: identity is the device, not the IP.

| Field | Value |
| --- | --- |
| Transport | UDP broadcast, port **41716** (not 1716, which KDE Connect uses) |
| Destinations | Subnet broadcast address of each non-internal IPv4 interface, plus 255.255.255.255 |
| Payload (JSON) | `service` = `imgdrop`, `v` = 1, `id` = server\_id, `port` = HTTP port, `ts` = unix time |
| Contains token? | Never |

### App connection logic

1. Try the cached address with `GET /health` (1 second timeout). If the returned `server_id` matches, use it.
2. Otherwise listen for a beacon for up to 5 seconds, match on `id`, update the cached address and retry.
3. Still nothing: show a clear error with a manual address entry as a last resort.
4. Repeat the same procedure whenever the OS reports a network change.

**Optional hardening (v1.1):** add an HMAC-SHA256 of `id|ts` keyed with the token to the beacon and have the app verify it before ever sending the token. This stops a rogue device on the LAN from luring the app into sending credentials. The risk is low on your own hotspot, so it can wait.

**Fallback discovery:** if raw UDP broadcast reception is restricted on the phone OS, advertise `_imgdrop._tcp` over mDNS instead (Android `NsdManager`, iOS Bonjour). Test early on the actual phone.

## 10. Phone app behaviour

- Pick or capture 1 to 20 images and add an optional note.
- **Compression before upload:** resize so the long edge is at most 1568 px (never upscale), encode WebP at quality 0.8 (JPEG 0.8 if WebP encoding is unavailable). Apply EXIF orientation first, then strip metadata so GPS location is not uploaded.
- Generate one `Idempotency-Key` when the user taps send. Reuse it on any retry.
- Send all images in one multipart `POST /groups`. Show progress, then the group ID and upload time.
- On network error, retry with the same key. No offline queue in v1.
- **Android:** allow cleartext traffic to LAN addresses via a network security config.
- **iOS:** set `NSAllowsLocalNetworking`, add `NSLocalNetworkUsageDescription`, and add the Bonjour service entry if mDNS is used.

## 11. Agent hook

A single Python file, `hook/imgdrop_hook.py`, standard library only.

**Config** (env vars or `~/.imgdrop/config`): `IMGDROP_URL` (default `http://127.0.0.1:8000`), `IMGDROP_TOKEN`, `INBOX_DIR` (default `./inbox`).

**Behaviour:**

1. `GET /groups/latest?unclaimed=1` with a 3 second timeout. If the server is unreachable or returns `204`, exit 0 with nothing on stdout (a one-line warning on stderr is fine).
2. Create `inbox/<group_id>/` and download each image through the API. Write to a temp name, then rename.
3. Write `manifest.json` containing group ID, `created_at`, note and the list of files with paths and sizes. Also write `inbox/latest.txt` pointing at the group directory, so the agent can find it again after a context reset.
4. Print the summary below to stdout.
5. `POST /groups/:id/claim` only after all files are written. On `409`, warn and continue.
6. Always exit 0. The hook must never block a session from starting.

**Stdout format (this becomes the agent's context):**

```
[imgdrop] New image group 01J... uploaded 2026-10-06 14:02 UTC (3 images)
Files: ./inbox/01J.../01.webp, 02.webp, 03.webp
Note from user: <note text, or none>
Manifest: ./inbox/01J.../manifest.json
These images are the task input for this session.
```

If several groups are unclaimed, the hook delivers only the newest and adds a line saying how many older ones remain. They stay `ready` and can be listed with `GET /groups?status=ready`.

**Wiring:**

- **Claude Code:** register the script as a `SessionStart` hook in `.claude/settings.json` (command: `python3 .claude/hooks/imgdrop_hook.py`). Its stdout is added to the session context.
- **Custom agent loop:** run the script before the first model call and prepend its stdout to the first message.

## 12. Server internals

```
imgdrop/
  server/
    src/
      index.ts          # wiring, startup, shutdown
      db.ts             # bun:sqlite, migrations
      auth.ts           # bearer middleware
      storage.ts        # tmp dir, rename, orphan sweep, magic-byte checks
      beacon.ts         # UDP broadcaster
      pair.ts           # config.json, QR print
      routes/groups.ts
    migrations/001_init.sql
    data/               # gitignored
  hook/imgdrop_hook.py
```

**Startup order:** load or create `config.json`, open the DB and apply migrations, sweep `storage/.tmp/` and any `storage/<id>/` directory with no group row (older than 1 minute), start Express on `0.0.0.0:8000`, start the beacon, print the QR code.

**Shutdown:** stop the beacon, close the HTTP server, close the DB.

**Backup and retention:** `sqlite3 data/app.db ".backup data/backup.db"` is enough for metadata, and the images are replaceable. Add an optional `bun run prune` that deletes claimed groups older than N days.

## 13. Security

- Bearer token on all data endpoints, constant-time comparison, never logged, never in the beacon.
- Route params are validated against the ULID pattern. No path is ever built from client-supplied names.
- Magic-byte type checks and enforced size and count limits.
- No CORS headers, since the client is native.
- Bind to `0.0.0.0`, but allow the port only on the private network profile. On Windows, make sure the hotspot network is classed as Private or the firewall will silently block it. On Linux, restrict with a firewall rule to the hotspot subnet.

## 15. Milestones

1. **M0, spike on the real hotspot:** Bun + Express + multer upload from curl or the phone, `bun:sqlite` WAL, and a UDP broadcast the phone can receive.
2. **M1, server core:** schema, `POST /groups`, read endpoints, claim and release, auth, orphan sweep.

4. **M3, discovery:** beacon and QR pairing.
5. **M4, app:** compression, upload, discovery, pairing screen.

## 16. Acceptance criteria

- Uploading 3 images creates exactly one group, 3 files on disk, 3 image rows, `status = ready`, and a server-set `created_at`.
- Killing the server mid-upload leaves no `ready` group, and the next start removes the leftover files.
- Repeating a request with the same `Idempotency-Key` does not create a second group.
- Starting an agent session after an upload puts the summary in context and the files in `./inbox/`. A second session right after is silent.
- A request with a wrong or missing token returns `401`.
- After the laptop's IP changes, the app reconnects within about 10 seconds with no user action.

## 17. Open questions

- Which app framework? Check UDP broadcast reception on the target phone before committing, since iOS is the stricter platform.
- Deliver only the newest unclaimed group, or all of them in order?
- Claim when the hook runs, or when the agent finishes? Claiming at hook time is simpler, and `release` covers failed runs.
- Retention period for claimed groups.
